# CrossTL → OBS Shaderfilter: verified material profile

**Status:** One real material profile, **not** a general GLSL, Shadertoy, or
ReShade converter. This is a build-time workflow, not a new OBS runtime.

## Why an OBS adapter is still needed

CrossTL 3.4 translates Glyphfield GLSL ES to DirectX-style HLSL. Shaderfilter
does not consume that form directly: its ordinary `.shader` is wrapped in a
libobs effect with `float4 mainImage(VertData v_in) : TARGET`,
`uv_size`, `elapsed_time`, and uniform-driven OBS properties. OBS's effect
parser and its OpenGL backend reject several otherwise valid HLSL constructs.

The tested adapter:

- Removes CrossTL's `cbuffer`, function prototypes and SV entry semantics,
  and maps time/resolution to the Shaderfilter host.
- Rewrites specific recognized matrix and unary-negative expressions into
  portable scalar math; disambiguates overloaded 2D/3D noise functions.
- Exposes nine real scalar sliders (warp, detail, frequency, grain,
  registration, density, brightness, rotation and scale); the reference
  palette is **fixed** in this first profile. It produces opaque procedural
  imagery rather than preserving incoming filter footage.
- Rejects unexpected uniforms and output shapes instead of silently emitting
  unsupported Shaderfilter code. Other shader families require their own
  observed, verified adaptation rules.

It does **not** provide extra render passes, arbitrary history buffers,
depth access, ML inference, advanced FFT/beat analysis or unsupported textures.
Those are host constraints, not translation errors. The existing
`data/examples/myrqyry/soft_register.shader` is a distinct hand-ported
**image-aware filter**; this example is a procedural **Shader Source**.

## Reproduce / use

This material originates from the **normalized** Glyphfield Soft Register
GLSL already used in SZION. The exact normalized source is preserved at
`tests/fixtures/glyphfieldSoftRegister.frag.glsl`; passing arbitrary unmodified
upstream GLSL is **not** supported.

```bash
uv run tools/convert_crosstl_to_shaderfilter.py \
  --profile glyphfield-soft-register \
  --input tests/fixtures/glyphfieldSoftRegister.frag.glsl \
  --output data/examples/myrqyry/glyphfield-soft-register-procedural.shader
python3 tests/verify_crosstl_shaderfilter_bridge.py
```

The generated `.shader` is checked in and does not require CrossTL or Python
while OBS is running. To try it interactively, add the plugin's standalone
**Shader Source**, enable file-backed shader selection, and choose
`data/examples/myrqyry/glyphfield-soft-register-procedural.shader`.
Use its standard shader wrapper (no full-effect override), and adjust Warp
or other exposed controls.

For the **optional full installed-plugin check** on Linux with libobs
headers, g++, Xvfb and a user-local Shaderfilter installation:

```bash
python3 tests/verify_crosstl_shader_source.py
```

Set `OBS_SHADERFILTER_MODULE` and `OBS_SHADERFILTER_DATA` to inspect another
plugin binary and its data directory. This runs in a disposable libobs process;
it does not change the installed binary, running OBS, scene, profiles, filters
or stream.

## Evidence (2026-10-26)

- Fresh CrossTL 3.4 translation, regenerated byte-for-byte shader, unknown
  profile rejection: PASS.
- Native **libobs 32.0.1 / Mesa llvmpipe OpenGL 4.5** compilation and actual
  offscreen GPU pixel readback (128×96): PASS. Changing `u_strength` from
  0 to 1.2 changed **10,987 pixels**.
- Separate real installed Shaderfilter 2.6.0 plugin `shader_source` test:
  **PASS**. Source dimensions **256×144**, Warp control present after shader
  initialization, no shader error, **30,186 pixels changed**.
- This does **not** establish visual parity to Glyphfield's WebGL2 output,
  real-hardware streaming FPS, Windows/D3D operation, or interactive OBS
  Studio UI acceptance.
